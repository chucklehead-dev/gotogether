CLI paired protocol:
One fixed baseline-built benchmark harness binary invokes each prebuilt CLI as a child process.
CLI command: gotogether evidence -history COPIED_FIXTURE_TREE
Startup, directory walking, discovery, selected saved-report readers and suite rendering are included; outputs discarded.
This command decodes/checks saved evidence/manifests; it does not freshly validate histories against a model.
Fixture copying/setup and initial acceptance invocation are outside timing; process/OS caches are warm.
6 before/after process pairs; order alternates old/new then new/old;10 timed CLI invocations/case/sample.
Benchmark binary working directory:cmd/gotogether.
GOTOGETHER_DISCOVERY_BENCH_BIN=<old-or-new> GOTOGETHER_DISCOVERY_BENCH_DIR=<copied-capture-tree> ./bench.test -test.run '^$' -test.bench '^BenchmarkEvidenceDiscoveryCLI$' -test.benchtime=10x -test.count=1
Child allocations are not measured by the parent CLI benchmark.
Captured-tree stdout/stderr were separately verified byte-identical between CLI versions.

Leaf profiling protocol:
The standalone Evidence.IsFile+Manifest.IsFile query workload is retained for both versions.
The historical baseline returns bool; the current source checks both errors from the new (bool,error) API.
This measures parser/leaf costs and allocations; candidate CLI can consolidate the pair, so this is not its full routing path.
GOTOGETHER_DISCOVERY_BENCH_DIR=<copied-capture-tree> ./bench.test -test.run '^$' -test.bench '^BenchmarkEvidenceDiscoveryLeaves$' -test.benchtime=100x -test.cpuprofile=cpu.pprof -test.memprofile=mem.pprof
